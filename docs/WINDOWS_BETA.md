# Windows 0.2.0-beta.3 — встановлення й підключення

Це тестова Windows x64-збірка з інсталятором, власним Python runtime і майстром підключення. Всередині — Android **0.1.14 / code 15** із чорними адаптивними віджетами. iPhone відкладено; Antigravity залишається експериментальним до перевірки на встановленому застосунку.

## Як це працює

Agent Beacon встановлюється на той комп’ютер, де працюють ваші агенти. Невеликий обробник отримує від них події початку роботи, питання та завершення, а Beacon показує стан у треї й локальній вебсторінці. Android отримує стан із цього комп’ютера через вашу локальну мережу. Закриття вкладки браузера не закриває Beacon.

Інсталятор розпаковує програму й runtime, створює ярлики та запис для видалення. Він **не підключає агентів до підтвердження в майстрі**. У майстрі ви вибираєте агентів, переглядаєте заплановані зміни й застосовуєте їх. Хуки — це маленькі команди в налаштуваннях агента, які повідомляють Beacon про стан; тексти запитів і відповідей на телефон не передаються. Авторизація Codex/Claude/Antigravity залишається в самих застосунках.

## Встановлення на іншому ноутбуці з нуля

Потрібні Windows x64, встановлений і авторизований підтримуваний агент та, для телефона, Android 8+ у тій самій довіреній Wi-Fi/LAN мережі. ARM64, Windows 7 і запуск усередині WSL цим пакетом не перевірені. Інтернет потрібний самим агентам та для отримання файлів; передавання статусу між ноутбуком і телефоном локальне.

1. Скопіюйте **AgentBeacon-Setup.exe** на ноутбук, наприклад через флешку чи приватне сховище. Посилання `127.0.0.1` працює тільки на комп’ютері, де Beacon запущений; це не загальнодоступне посилання для Telegram. Python, Git, папку вихідного коду та `.tools` переносити не потрібно.
2. Відкрийте EXE від свого звичайного користувача Windows. Початкова інсталяція не потребує адміністратора. Прочитайте шлях, виберіть ярлик і натисніть **Встановити й відкрити**. Ця бета ще не має Authenticode-підпису; системне попередження можливе. Якщо Windows блокує файл, не вимикайте захист системи — перевірте походження й контрольну суму пакета.
3. У браузері відкриється майстер. Позначте лише потрібних агентів. Для телефона ввімкніть LAN. Натисніть **Переглянути зміни**, перегляньте список, потім **Підключити вибраних агентів**. Резервні копії наявних налаштувань створюються автоматично.
4. Перезапустіть вибраного агента або відкрийте новий локальний чат. Напишіть коротке завдання. У кроці перевірки має з’явитися **отримана подія**, а не лише повідомлення про записані хуки. Якщо потрібна допомога, кнопка **Допомогти підключити** дає готовий промпт із правильною командою саме для цього ноутбука.
5. Встановіть APK з QR **встановлення** у майстрі. Якщо Android просить дозвіл встановлення з цього джерела, рішення приймаєте ви в системному діалозі. Уже встановлений Agent Beacon оновлюйте поверх попередньої версії, без видалення.
6. У майстрі створіть окремий QR **підключення**. На телефоні відкрийте Agent Beacon → **Scan QR** → відскануйте його → **Connect**. Код одноразовий, чинний дві хвилини; прострочений створіть заново. Дозвольте сповіщення, якщо потрібні фоновий статус і звукові сигнали.
7. Увімкніть **Background monitoring**, додайте віджет і перевірте коротке завдання: червоний під час роботи, зелений після завершення; питання має дати жовтий стан. Початок роботи й звичайні оновлення тихі; питання та завершення можуть дати звук і вібрацію згідно з дозволами Android.

На новому ноутбуці потрібне перше підключення QR: це інший сервер. Не копіюйте вручну приватні токени чи весь каталог даних зі старого ПК. Після успішного підключення перезапуски й зміни порту на цьому ж сервері не потребують нового QR — відкрийте **Check & connect**, якщо автоматичне відновлення затрималося. Збережене підключення Android зараз перемикається на обраний комп’ютер; одночасний огляд кількох ПК окремою функцією не реалізований.

## Віджети й значення станів

| Колір / напис | Що означає |
| --- | --- |
| Червоний / Working | Агент виконує запит. |
| Жовтий / Needs you | Потрібна відповідь або ще чинне нагадування про питання. |
| Зелений / Ready | Готовий до нового запиту; це не оцінка правильності результату. |
| Сірий / No update, Unknown | Немає підтвердженого свіжого стану. |
| Reconnecting / Syncing | Коротке відновлення зв’язку; попередній стан утримується лише в обмеженому вікні. |

На Android затисніть вільне місце домашнього екрана → віджети → Agent Beacon. Компактний віджет показує загальний стан; **Agent overview** має окремі рядки агентів. У застосунку → **Widget settings** виберіть конкретний великий віджет, 1–3 агентів, порядок і лічильники, потім **Save widget**. Налаштування кожної копії незалежні; вони не змінюють глобальні сповіщення.

Картки чорні, без бічної смуги. У низькій картці заголовок ховається, зберігаючи рядки; у вузькій лишаються назви та кольорові крапки. Щоб бачити текст стану, збільшіть ширину. При дуже великому системному шрифті збільшіть також висоту. Число після стану, наприклад `Working · 3`, означає **всього 3 актуальні чати цього агента**, серед яких є активний; не обов’язково всі три працюють. Один чат окремим числом не позначається. Готові чати залишають актуальний список через 30 хвилин без активності та повертаються при новій роботі.

Для Samsung LockStar додайте той самий віджет через Good Lock, як уже робили. Розміри, відступи та дозволи на екрані блокування контролює також Samsung. Перемикач показу статусу в сповіщенні на заблокованому екрані не встановлює LockStar й не гарантує доступність віджетів на всіх моделях Android.

## Якщо щось не підключається

| Симптом | Що перевірити |
| --- | --- |
| Хуки записані, але стан сірий | Перезапустіть агента / створіть новий локальний чат і дайте реальний запит. Перевірте, чи підтримується саме цей режим агента. |
| На ПК усе видно, телефон не бачить сервер | Увімкніть LAN у майстрі, перевірте однакову мережу, VPN та ізоляцію клієнтів гостьового Wi-Fi. За потреби скористайтеся окремою кнопкою firewall і прочитайте запит Windows. |
| Після зміни IP або порту втрачено зв’язок | Залиште одну копію Beacon, натисніть **Check & connect**. Автопошук використовує UDP; якщо мережа його блокує, скористайтеся доступним у застосунку ручним підключенням/новим QR. |
| Моніторинг сам зупинився | Після 30 хвилин без відповіді ПК це очікуване збереження батареї. **Check & connect** відновлює роботу. ПК у сні не може передавати статус. |
| Немає звуку або сповіщень | Перевірте дозволи Agent Beacon, канал питань/завершень, режим «Не турбувати», гучність і фонові обмеження Android. Оновлення статусу саме по собі не повинно дзвеніти. |
| Після оновлення віджет показує старе | Відкрийте застосунок і **Check & connect**; за потреби вимкніть та знову ввімкніть Background monitoring. Дані застосунку не очищайте. |
| Майстер відкрився на іншому порту | Це нормально: зайняті порти обходяться автоматично. Відкривайте Beacon через ярлик або трей замість старої закладки. |

Якщо проблема повторюється, зафіксуйте версії Windows/Android/Beacon, назву агента та послідовність дій. Журнал знаходиться в каталозі даних нижче; перед передаванням перегляньте його й приховайте приватні шляхи та ідентифікатори. Не надсилайте токени, QR підключення чи повні конфігурації облікових записів.

## Мова Android

У головному екрані Android доступний вибір Автоматично / Українська / English. В автоматичному режимі лише англійська мова телефона обирає English; решта — українську. Короткі написи віджетів залишаються англійською. Вибір мови не змінює pairing і не відтворює звукові сигнали повторно.

## Що робити користувачу

1. Запустіть **AgentBeacon-Setup.exe**, виберіть, чи потрібен ярлик, і натисніть **Встановити й відкрити**. Python, pip і команди в терміналі не потрібні. Файли встановлюються тільки для вашого користувача.
2. У майстрі виберіть Codex, Claude Code та/або Antigravity. Увімкніть доступ для телефона, якщо він потрібен. **Переглянути зміни → Підключити вибраних агентів** записує хуки з резервними копіями. Технічний список файлів доступний у розкривному блоці.
3. Перезапустіть агента або відкрийте новий локальний чат і надішліть короткий запит. Майстер розрізняє «Хуки записано» та «Отримано подію від агента»: успішний запис конфігурації сам по собі не означає підтвердженого стану.
4. Для нового телефона: QR встановлення APK відкривається звичайною камерою; окремий одноразовий QR підключення сканується **всередині Agent Beacon на Android → Scan QR → Connect**. Комп’ютер і телефон мають бути в одній довіреній мережі.

Якщо автоматичне налаштування заблоковано, відкрийте **Допомогти підключити** у картці агента, скопіюйте готовий промпт і вставте його в Codex або Claude Code. Промпт містить точну команду встановленого обробника, просить спершу показати план і не змінювати авторизацію, .env, дозволи інструментів чи firewall. Він не містить токенів або текстів ваших чатів.

Авторизуватися й підтвердити довіру до папки потрібно в самому агенті. Звичайна вкладка Claude Chat, хмарні, WSL та SSH-сесії цим локальним підключенням не охоплюються. Виявлення за локальними файлами/командою є підказкою, а не доказом активного підключення.

## Перехід із запуску з папки проєкту

Закрийте старий **Agent Beacon** через його значок у треї перед остаточним переходом; самі Codex/Claude та їхні чати видаляти не потрібно. Старі файли конфігурації та реєстр телефонів залишаться доступними для перенесення.

Майстер може знайти реєстр уже підключених телефонів за впізнаними старими хуками Beacon. Якщо знайдено рівно одне валідне джерело, з’явиться **Зберегти телефони зі старої копії Beacon**. Після перегляду й застосування реєстр копіюється тільки в порожній реєстр нової копії; джерело зберігається. Дані чатів і plaintext токени не копіюються. Потім на Android натисніть **Check & connect**.

Якщо одночасно працюють дві копії, порт автоматичного пошуку може бути зайнятий старою копією. Майстер показує це окремо. Залиште одну потрібну копію та повторно відкрийте встановлену програму. За кількох неоднозначних джерел чи вже непорожнього нового реєстру автоматичного злиття немає: поточні підключення не перезаписуються.

Розпізнані старі source-хуки Beacon можуть бути замінені на стабільний встановлений AgentBeacon-Hooks.exe. Сторонні хуки зберігаються, попередній Codex notify callback продовжує викликатися. Невпізнані або змінені конфігурації можуть потребувати ручного перегляду через допоміжний промпт.

## Мережа, автозапуск і щоденна робота

Перший запуск доступний тільки на комп’ютері. LAN вмикається вашим вибором у майстрі. Якщо телефон не підключається, перевірте приватний профіль Windows, Wi-Fi/VPN та кнопку **Дозволити Beacon у брандмауері Windows…**. Вона окремо викликає запит адміністратора; правило обмежене конкретним EXE, Private-профілем і LocalSubnet. UDP дозволяється для порту 47665; TCP — для цього EXE, щоб зміна локального порту не ламала правило. Профіль мережі автоматично не змінюється.

Програма запам’ятовує порт, а якщо він зайнятий, шукає вільний у 8765–8815. Власний користувацький реєстр телефонів переживає рестарти. При зміні мережі або набору агентів сервер коротко перезапускається, а майстер відкривається за поточною адресою. Лише автентифікований локальний користувач може змінювати налаштування; токен телефона дозволяє читати стани, але не цей майстер.

Автозапуск Windows — окрема необов’язкова галочка, початково вимкнена. Закриття браузерної вкладки залишає програму в треї. Для повного завершення скористайтеся меню трея. Повторний запуск ярлика відкриває вже запущену копію, а не створює другу для того самого каталогу даних.

## Де зберігаються файли

- Програма: `%LOCALAPPDATA%\Programs\AgentBeacon`.
- Налаштування, реєстр телефонів, черга подій і обмежений діагностичний журнал: `%LOCALAPPDATA%\AgentBeacon`.
- Резервні копії конфігурацій агентів: поряд із відповідними файлами, з суфіксом `.agent-beacon.<sha256>.bak`.

Інсталятор перевіряє контрольну суму payload, розпаковує в окремий каталог і зберігає попередню версію в `.AgentBeacon-previous-*` поруч. Він відмовляється замінювати невідому папку без маркера встановлення. Перед заміною зупиняється тільки відповідна встановлена копія з перевіреним PID, часом створення й ідентичністю локального сервера. Помилка на етапі заміни каталогу відновлює попередній каталог. Помилки ярликів/реєстрації можуть потребувати повторного запуску інсталятора; це не транзакція над усією Windows.

Видалення доступне через список програм Windows або Uninstall-AgentBeacon.exe. Окрема галочка прибирає лише незмінені/впізнані хуки цієї копії з резервними копіями; інші налаштування й подальші правки зберігаються. Дані телефона залишаються. Змінені чи сторонні файли в папці програми не видаляються. Правила firewall автоматично не видаляються. Попередні версії залишаються для ручного відновлення.

## Перевірки та межі бети

Зібрано Windows x64 installer і portable ZIP. Перевіряються фактичні frozen EXE, їхній helper зі stdin/stdout, запуск без Python у PATH, шляхи з пробілами/апострофом/українськими літерами, HTTP майстер, native tray, зміна порту, pairing і видалення в окремому робочому каталозі. Інсталятор окремо перевіряє власний payload і завантаження вбудованого Tcl/Tk у звичайному Windows TEMP. Майстер оглянуто в браузері.

Це не перевірка на чистій Windows-машині без встановленого Python і не повний ручний прохід native-вікна інсталятора, UAC, ярликів, реєстру та фізичного Android. Ці перевірки потрібні до публічної бети. Збірка не має Windows Authenticode-підпису; відсутність SmartScreen-попереджень не обіцяється. Поточний Android APK теж залишається debug review-збіркою з попереднім ключем.

## Відтворення збірки розробником

Пакувальник і службові залежності встановлено за дозволом користувача лише в `.tools/windows-build`; глобальний Python не змінювався. Точні версії: [build-requirements.txt](../apps/windows/build-requirements.txt). Інсталятор реалізований у проєкті, без Inno Setup та нових платних сервісів.

```powershell
python -m venv .tools/windows-build
& .\.tools\windows-build\Scripts\python.exe -m pip install -r apps/windows/build-requirements.txt
python scripts/windows/build_beta.py
```

Перед новою інсталяцією залежностей потрібен звичайний дозвіл власника проєкту. Сам build_beta.py нічого не завантажує. Він збирає два EXE з одним набором runtime-файлів: windowed AgentBeacon і console-subsystem helper із раннім приховуванням лише власної консолі, що зберігає stdin/stdout. Окремий onefile setup містить перевірений ZIP runtime. Підхід ґрунтується на [офіційній документації PyInstaller](https://pyinstaller.org/en/stable/usage.html).

Для нової копії вихідного коду спершу зберіть Android або покладіть перевірений APK із відповідного релізу в `dist/AgentBeacon-debug.apk`: Windows-збірка включає цей файл для встановлення на телефон. Вихідний ZIP навмисно не містить бінарних збірок чи приватного build-середовища.

Portable ZIP призначений для ручної перевірки: розпакуйте всі файли в постійний каталог і запустіть AgentBeacon.exe. Після налаштування хуків не пересувайте цей каталог без повторного підключення. Звичайним користувачам простіше використовувати setup EXE з ярликами та видаленням через Windows.

У цьому sandbox Tcl не міг завантажити бібліотеку поза робочим каталогом, хоча файли були на місці. Для збирання стандартний каталог Tcl/Tk скопійовано з наявного Python в `.tools/windows-tcl`, без зміни глобальної інсталяції; build script використовує локальні TCL_LIBRARY/TK_LIBRARY лише для процесів збирання. Зібраний setup окремо пройшов payload/Tcl-перевірку поза sandbox у звичайному TEMP. Ліцензії runtime додаються до дистрибутива.

Артефакти та контрольні суми: `dist/windows/`. Приватні каталоги .beacon, .cache, .tools, дані облікових записів, pairing та ключі підпису в дистрибутив не потрапляють. Публічний код: [Karaoki15/agent-beacon](https://github.com/Karaoki15/agent-beacon); готові файли — у GitHub Releases.
